# 0.0.4-beta.1

This is a prerelease for further testing. The stable release remains 0.0.3.

## Changes

- Integrate [PR #2](https://github.com/kpaede/docxidian/pull/2), preserving spaces typed into the hidden ProseMirror editor.
- Update the DOCX editor and translations from 1.0.1 to 1.9.0, JSZip, ProseMirror, and compatible development dependencies.
- Keep the editor session alive across saves, renames, and settings changes. Previously, an mtime-based React key could reload an old input buffer and subsequently overwrite saved edits.
- Replace the old vertical-ruler DOM-position workaround with consistent section properties and prevent layout scroll anchoring from moving the viewport during ruler drags.
- Clean up injected editor styles on plugin unload and discard stale concurrent embed loads before they can create orphaned React editors.
- Disable the editor's separate local-file-open action so the host vault remains responsible for opening documents.
- Correct version mapping updates and mark beta tags as GitHub prereleases automatically.

## Ruler investigation and implementation

The earlier `cefb18e` workaround wrote marker positions from captured document snapshots using two animation frames and a 50 ms timeout. A fast, steadily downward drag reproduced 13 backwards marker movements. The native ruler also read the first section's properties while its margin callback updated only `finalSectionProperties`.

Correcting the property mismatch exposed a second feedback loop: layout scroll anchoring moved the scroller while the next mouse event calculated its margin relative to the moving ruler. At 75% zoom this could escalate into large viewport jumps.

The build adapter in `build/editor-patches.mjs` applies narrowly checked corrections to the pinned editor 1.9.0 source while bundling:

- Rulers and page setup update both representations of the final section. Earlier sections and document content retain their existing objects and values.
- The vertical ruler reads the same final-section properties as its callbacks, preserving the previous integration's choice of section.
- During a ruler drag, layout does not capture or restore a text scroll anchor. Pending scroll restoration is also suppressed. A short period after mouseup covers the final layout; regular anchoring resumes afterward.

The old delayed marker writes are removed. Installed dependency files are not modified. Every source replacement must match exactly once; an upstream change fails the build and requires reviewing or removing these workarounds. Regression tests cover property preservation, multiple sections, local drag-state cleanup, and that build guard.

## Validation

Tested in the actual Obsidian desktop vault on macOS, Obsidian 1.15.0 (installer 1.14.5), with synthetic DOCX and Markdown fixtures.

- Actual keyboard input: single/repeated spaces, paragraph breaks, and Unicode.
- Manual save and reopen, with ZIP integrity checks and assertions against saved WordprocessingML.
- Search/replace, autosave, rename, and preservation of edits across language/ruler setting changes.
- Comments, tracked insertions/deletions, headers, tables, long-document pagination, and read-only native Markdown embeds.
- All seven editor languages, failed-write recovery, and byte comparisons of existing open DOCX files.
- Native mouse dragging and fast scripted drags of both vertical handles in both directions at 75%, 100%, and 150% zoom; marker monotonicity, stable scroll position, page-content alignment, multi-section preservation, saved/reopened margins, and autosave.
- Unit tests, lint, production build, clean lockfile installation, and npm audit of production dependencies.

The final automated runs passed 15 general vault checks, 11 ruler checks, and 5 unit tests. Three consecutive plugin reloads kept stylesheet/editor counts stable and preserved the three command registrations. A clean build produced byte-identical release artifacts.

Repeat the interactive tests with a running Obsidian app and its CLI enabled:

```sh
OBSIDIAN_TEST_VAULT="Test vault" npm run test:vault
OBSIDIAN_TEST_VAULT="Test vault" npm run test:rulers
```

The scripts use dedicated fixture folders and restore their temporary settings. Avoid manually interacting with the test pane during automation. `OBSIDIAN_CLI` overrides the default macOS CLI path; `OBSIDIAN_TEST_REPORT` writes a JSON report. Fixtures remain available for inspection.

## Remaining limits

Physical iOS/Android devices and older Obsidian versions were not tested. The beta still uses the deprecated 1.x editor package names; migration to the renamed 2.x packages requires separate compatibility work. React 18, TypeScript 5, and ESLint 9 remain on compatible major versions.

The integrated rulers continue to edit the final section. Automatically selecting a section based on the currently visible page is not implemented.

Production dependency audit: no known vulnerabilities. The development dependency audit still reports 23 moderate findings in the lint-tool dependency tree; no forced incompatible overrides were applied.
